## Decisions

### Owner (2026-11-07)

- **O1 · Start only on a clean tree.** The uncommitted deployments/service work must be committed or parked by its owner before F0a. The campaign does not stash, commit, revert, quarantine, or build on it. Reversal: the owner explicitly authorizes a campaign worktree; then F0a records that deviation and the final merge point.
- **O2 · System metadata refreshes per fleet mount and on manual refresh.** OS, kernel, CPU model, and agent version are not telemetry and change rarely. Remove the host `/system` request from the 15-second fleet tick; keep it on mount and manual refresh. Reversal: a user-visible need for sub-five-minute kernel/agent metadata on an open fleet page.

### Prescribed

- **S1 · Keep the existing async model.** `loadQuery()` stays, and its `onCleanup` registration is correct under Solid 2: a memo's cleanups are parked on each recompute and run when the next frame commits. A host A→B probe confirmed the old history request fails with `net::ERR_ABORTED`. Do not replace `createMemo`, `refresh`, `Loading`, `Errored`, or `createUpdateEffect` with a query framework. Fixes stay inside that model. Reversal: a test shows a late result overwriting a new subject that the model cannot express.
- **S2 · One small conditional-cache type.** The four maps in `api.ts` become one cache type with the existing 32-entry limit plus an 8 MiB retained-bytes budget per cache. Retained bytes are the response frame's byte length, doubled when `openHistory` reports `zeroCopy: false`. A `304` touches recency; a per-path request sequence lets only the newest started request install; a `304` whose `ETag` differs from the cached one is retried once without `If-None-Match`. No second cache of raw frames, no global cache of decoded tables. Entries live only in the page's module scope, keyed by same-origin relative path; a reload or a different installation origin starts empty, and nothing is persisted. If F0b's 100-navigation trace keeps every cache under 4 MiB, keep the entry limit and record why the byte bound is unnecessary. Reversal: a real trace exceeds 8 MiB after eviction; lower the budget, do not remove it.
- **S3 · Keep the columnar representation.** `decodeHostHistories()` stops calling `decodeFleetHistories()` and then decoding filesystems again; it decodes the fleet four once and replaces only `block`. No point objects, no new decode layer, no copy of the frame. Reversal: a consumer depends on two distinct filesystem table objects; none does.
- **S4 · Bounded concurrency, not batches.** Fleet rows keep 4 in flight, but a settled host starts the next instead of waiting for its batch. Concurrency never rises above 4, ordering is preserved, and the same signal aborts every in-flight request. Reversal: the scheduler is slower on the F0b fixture or lets a fifth request start.
- **S5 · Defer by subject, not by widget.** Projects rows use the ledger's current/previous histories for their expanded trends when the ledger loaded; if the ledger failed, the row fetches its range history only when expanded, so a ledger failure does not erase trends. Remove the eager per-row range-history effect. The project deployment comparison runs only while the `deploys` section is open or a deployment deep link opened it. Issue occurrences run only while `errors` is open. Fleet system metadata follows O2. Health and open-issue counts stay eager because the project pills use them. No new endpoint. Reversal: a deferred request becomes a user-visible wait over 200 ms on the local fixture, or a section needs the data before it opens.
- **S6 · Charts update in place.** Keep uPlot. A plot is rebuilt only when a field captured at construction changes; telemetry changes use `setData`, view changes use `setScale`. Do not add a global derived-series cache. Do not trade a rebuild for a stale chart. Reversal: `setData` cannot express a changed construction field, or a rebuild is measured cheaper than an in-place update.
- **S7 · Observability clears on a subject change.** When the issue filter, trace filter, route, band, window, or selected trace/issue changes, the dependent panel shows its loading state; data from the previous key is never rendered under the new key. A refresh of the same key may keep the previous value. No generic state machine; use the existing signals plus a key check, or one domain helper if three or more resources repeat it. Reversal: clearing loses useful same-key refresh value or breaks a deep link.
- **S8 · Bundle boundaries follow rendering.** uPlot must not load on a route whose initial view has no chart: the projects overview (all rows collapsed) and the project page (all sections closed). Load Signals, Errors, Requests, and the projects Trends on first open; deep links open their section and load immediately. No `manualChunks` unless F6's chunk report shows duplication that boundaries cannot fix. Both targets must serve the lazy chunks identically. Reversal: a boundary removes under 5% of the route's initial gzip or makes a section open slower than 200 ms locally.
- **S9 · Route payload gates.** Projects initial JavaScript (gzip) at most 80% of baseline; project initial at most 85%; fleet, host, and service no more than 5% worse; a fully open project no more than 105% of its baseline total. A route's request count never grows without a recorded reason. Reversal: the owner sets a different product budget; the gates move together, not one route at a time.
- **S10 · Tests use controlled timing.** Lifecycle and observability tests use deferred route responses and Playwright's clock, never real sleeps. Cache tests are Node tests with a stubbed `fetch` and the existing independent `encodeHistory` oracle. Existing screenshot goldens do not change; a diff is a failure unless the item explicitly says the visual is intended. Reversal: the browser cannot control a specific interval; use a deterministic deferred route, never a sleep.
- **S11 · No server, wire, auth, or agent change.** If an optimization genuinely needs one, stop and surface it as a contract change; it must work on both Cloudflare and Node with contract and integration coverage. The campaign does not redesign the protocol.
- **S12 · Documentation.** `docs/frontend-efficiency.md` holds the method, raw tables, and before/after results. Update `docs/architecture.md` only where behavior changes (system refresh cadence, deferred sections, cache bound). `docs/testing.md` gains the new spec names and the bench commands.

## Known traps

- **The start checkout is dirty.** The uncommitted service work is not a baseline. Do not measure, build on, stage, or commit it.
- **A fresh worktree needs both Worker builds** before `make cloudflare-test`, or four CLI tests fail on missing `.cloudflare/output` files. Run `pnpm --filter @stats/telemetry build` and `pnpm run build:observe` first. This is a loop prerequisite, not a campaign fix.
- **The preview serves uncompressed assets.** `bench-ui` `jsKb` is raw transfer; compare gzip only from `bench-bundle`, and do not call a preview byte a production byte.
- **One build at a time.** `make dashboard-test`, `make cloudflare-test`, `make node-e2e`, and the preview all rebuild `.cloudflare/output`; never run two at once.
- **Playwright ports.** A stale server on 4173/4175 makes a run fail with `EADDRINUSE`; let Playwright own its servers and do not run the UI suite concurrently with another.
- **`loadQuery` ownership is correct.** A memo's cleanup is parked per pass and runs when the next frame commits; the host A→B probe aborted the old request. Do not "fix" it into an effect or a manual controller.
- **`createUpdateEffect` skips its first run by design.** Initial data comes from the memo; the effect handles changes. Removing the skip duplicates every initial request.
- **`decodeHostHistories` double decode** is in `history.ts:166`; the returned filesystem table is the second one.
- **The cache LRU does not touch on 304** (`getHistory` returns before `rememberConditional`), and an older response can replace a newer one.
- **uPlot lives in `shared`.** The projects overview imports `PanelChart` only for collapsed Trends, and the project page imports chart components for closed Signals. Both load 30 KB gzip of chart code before any chart is shown.
- **`ProjectsPage` requests `from=0&to=0`** while its ledger waits for the first history; gate the ledger on a known window.
- **The observability trace/occurrence signals are not cleared at key change.** `Observe.tsx:175` and `:192` only clear on a null id; a new id can render the previous detail until the new response lands.
- **ProjectPage remounts via keyed `Show`** on the project id, so cross-project state is already reset; do not add another keying layer.
- **Screenshots are WebP and are not updated** to absorb an accidental visual change.

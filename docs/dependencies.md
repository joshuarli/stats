# Dependencies and toolchain

Pins: Rust `nightly-2026-09-15` (`rust-toolchain.toml`), Node from `.node-version`, pnpm 12.15.0 (both enforced by `make node-ready`), and Zig 0.17.0 plus `python3` (both checked by `agent/scripts/build-static.sh`). Every npm dependency is pinned exactly in `cloudflare/package.json`. Build and deploy use `cloudflare.config.ts`, `vite.config.ts`, and `cf`; the project declares no Wrangler dependency and never runs the Wrangler CLI.

## Agent crates

The agent uses `deser` 0.10.2 and `deser-json` for its JSON config, the
block-latency snapshot, and `--once` output (`deser-value` is now a test-only
dev-dependency), and `h12tiny-client-sync` 0.7.0 with its `tls` feature for
HTTPS, replacing
`serde`, `serde_json`, `ureq`, `rustls` with `ring`, and `rustls-native-certs`.
TLS now runs on Graviola through `h12tiny-tls-system`. The h12tiny crates come
from the `mycrates` registry configured in `agent/.cargo/config.toml`.
The binary ingest codec (`agent/src/wire.rs`, `cloudflare/src/ingest/`) is
written by hand against `docs/protocol.md` and adds no dependency on either
side: no serialization framework, schema compiler, WASM, or compression
library.

`h12tiny-client-sync` 0.7.0 depends on `h12tiny-client-normalize` and
`h12tiny-tls-system` as crates.io packages, so those two resolve through the
crates.io mirror. The mirror carries them because the agent lockfile was
imported into it as project `stats-agent`; a new h12tiny release needs the
same import before the agent can move to it.

The client bounds the request write and response-header read with the request
timeout; the agent bounds the body read to the remainder of the same deadline.
Connection setup is bounded separately by the same duration.

## esbuild in `@stats/telemetry`

The production build and deploy are esbuild-free: `vite build` writes the Build
Output Specification and `cf deploy --prebuilt` uploads it. The remaining
esbuild comes from `@cloudflare/vitest-plugin@1.4.11`, which hard-depends on
`esbuild@0.28.2` and `wrangler@4.156.0`. Vite 8 lists esbuild only as an
optional peer; it disappears once nothing else installs it.

The plugin's only direct esbuild use is its upstream `guess-exports` build
step:

```ts
await build({ entryPoints: [entryFile], bundle: false, metafile: true, ... })
```

It parses the entry and reads `metafile.outputs[*].exports` to discover export
names; it never bundles. A tsrs or Oxc parser can replace that in about 50
lines.

That alone does not remove esbuild. The plugin also uses wrangler's
`unstable_readConfig`, `unstable_convertConfigBindingsToStartWorkerBindings`,
and `unstable_getMiniflareWorkerOptions`, and wrangler depends on esbuild.
Vendoring the plugin means forking its ~15 source files from workers-sdk (the
published dist is a 2.8 MB minified bundle containing wrangler) and
reimplementing config parsing and Miniflare options against
`@cloudflare/config` plus Miniflare, then rebasing across Miniflare 5 beta and
workerd updates. The license is MIT, so the cost is ownership, not permission.

Decision: keep the plugin. The dependency is dev-only and never ships. The real
removal path is upstreaming the wrangler-to-`@cloudflare/config` migration in
the plugin.

## Platform binaries in lockfiles

Lockfiles keep every optional platform package. Neither
`npm install --package-lock-only --omit=optional` nor pnpm 11's
`supportedArchitectures` removes foreign entries; both managers filter what
they install, not what they resolve. Only `@tsrs/darwin-arm64` is installed on
this machine. Hand-pruning the lockfile is regenerated by the next install and
breaks frozen installs elsewhere. Leave it.

## Miniflare as a direct dev dependency

`cloudflare/test/observe-e2e/` runs the built `stats` and `stats-observe`
bundles together in workerd with a tail consumer attached, which the vitest
pool cannot do. It imports `miniflare` directly, pinned to
`5.20261023.3-beta`, the version `@cloudflare/vitest-plugin` already
installs. The pin adds no package to the tree, and nothing ships with it.
Upgrade it together with the plugin.

## Source-map resolver in `stats-observe`

`@jridgewell/trace-mapping` 0.3.31 resolves caught-error frames to original
files and lines in `cloudflare/src/observe/core/symbolicate.ts`. It is MIT,
pure JavaScript with two small dependencies (`@jridgewell/sourcemap-codec`
and `@jridgewell/resolve-uri`), already in the tree through Vite, and the
resolver that Node and most JavaScript tooling use; a hand-written VLQ
decoder would be more code to own for no gain. Only `stats-observe`
bundles it: measured on 2026-11-04 it grew that Worker from 14.8 to 20.5 KB
gzipped, and the `stats` Worker and the dashboard do not include it.
`@jridgewell/sourcemap-codec` is a direct dev dependency at the same
version so tests can build small maps.

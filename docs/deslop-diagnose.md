## Ownership and risk order

1. **Host identity, ingest and stored history:** the agent loads owner-only config and token files (`agent/src/config.rs:139`), encodes batches (`agent/src/wire.rs:102`) and retries through a bounded queue (`agent/src/runtime.rs:158`). The shared HTTP router forwards host ingest (`cloudflare/src/core/http.ts:183`); `Installation.ingest` decodes, authenticates, checks duplicates and writes samples and rollups (`cloudflare/src/core/installation/installation.ts:522`). These are highest consequence because incorrect admission or acknowledgment can lose or corrupt host history. The shared frame corpus and the Node installation tests exercise malformed frames, exact canonical samples, duplicate replay and no writes on bad credentials. The transaction adapter and its nested rollback tests are at `cloudflare/src/node/sql.ts:18` and `cloudflare/test/node/ports.test.ts:25`.
2. **Access and tenant separation:** a network caller may attempt to read dashboard data or submit another host or service's telemetry. `cloudflare/src/core/http.ts:183` separates bearer-only ingest from authenticated data and assets; Node's peer/identity decision is `cloudflare/src/node/tailscale.ts:16`, and the Worker gateway checks its secret and identity at `cloudflare/src/cloudflare/gateway.ts:8`. Service token verifiers are checked in `cloudflare/src/core/installation/services.ts:279`. The local Node tests cover absent identity, non-loopback peers, cross-site writes, separate deploy and ingest tokens and observe service separation. This assumes the stated trusted proxy/socket deployment, not arbitrary local processes supplying identity headers.
3. **Observation persistence and delivery:** `cloudflare/src/observe/ingest/codec.ts:74` rejects duplicate IDs in one batch; `cloudflare/src/observe/core/store.ts:625` transactionally checks stored event identity and inserts accepted events. The Node HTTP harness provisions synthetic credentials and verifies initial delivery, replay and reads (`cloudflare/test/node/observe-ingest.test.ts:79`). Producer queue, retry and shutdown contracts are documented in `packages/producer/README.md`; no independent producer failure campaign was run here.
4. **Operator and presentation paths:** CLI argument rules and routing are owned by `cloudflare/src/cli/run.ts:30`, with bounded and cancellable HTTP at `cloudflare/src/cli/http.ts:87`. The contract test covers exit codes, redirects, retry and malformed responses. Dashboard response decoding is in `cloudflare/src/client/api.ts:64`; counter regression gaps are asserted in `cloudflare/test/aggregate.test.ts:105`. Fixed Analytics query builders are called by `cloudflare/src/cloudflare/projects/collector.ts:14`. These paths were sampled, not exhaustively audited; UI rendering, provider behavior and actual remote consumers were not exercised.

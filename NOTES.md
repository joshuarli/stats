# Notes

## esbuild in `@stats/telemetry`

The production build and deploy are esbuild-free: `vite build` writes the Build
Output Specification and `cf deploy --prebuilt` uploads it. The remaining
esbuild comes from `@cloudflare/vitest-plugin@1.4.11`, which hard-depends on
`esbuild@0.28.2` and `wrangler@4.156.0`. Vite 8 lists esbuild only as an
optional peer; it disappears once nothing else installs it.

The plugin's only direct esbuild use is `src/pool/guess-exports.ts`:

```ts
await build({ entryPoints: [entryFile], bundle: false, metafile: true, ... })
```

It parses the entry and reads `metafile.outputs[*].exports` to discover export
names; it never bundles. A tsrs or Oxc parser can replace that in about 50
lines.

That alone does not remove esbuild. The plugin also uses wrangler's
`unstable_readConfig`, `unstable_convertConfigBindingsToStartWorkerBindings`,
and `unstable_getMiniflareWorkerOptions`, and wrangler depends on esbuild.
Vendoring the plugin means forking its ~15 source files from workers-sdk (the
published dist is a 2.8 MB minified bundle containing wrangler) and
reimplementing config parsing and Miniflare options against
`@cloudflare/config` plus Miniflare, then rebasing across Miniflare 5 beta and
workerd updates. The license is MIT, so the cost is ownership, not permission.

Decision: keep the plugin. The dependency is dev-only and never ships. The real
removal path is upstreaming the wrangler-to-`@cloudflare/config` migration in
the plugin.

## Platform binaries in lockfiles

Lockfiles keep every optional platform package. Neither
`npm install --package-lock-only --omit=optional` nor pnpm 11's
`supportedArchitectures` removes foreign entries; both managers filter what
they install, not what they resolve. Only `@tsrs/darwin-arm64` is installed on
this machine. Hand-pruning the lockfile is regenerated by the next install and
breaks frozen installs elsewhere. Leave it.
